# Prompt Hygiene

## What good inputs look like
Include:
- Goal (what outcome you want)
- Constraints (stack, versions, “do not change X”)
- Current behavior vs desired behavior
- Examples (requests/responses, UI screenshots, logs)
- Definition of done (acceptance criteria)

## Ask for structure
For anything beyond a tiny change, request:
- Approach (short)
- Implementation details (code)
- Edge cases and risks
- Tests
- Rollout notes (if applicable)

## Avoid
- Vague prompts (“make it better”, “optimize everything”)
- Overly broad tasks in one go (split into tickets)
- Copy/pasting huge files without pointing to the relevant parts
